# 0.1.1 — 2026-10-21

## Added

- **`interpro_search_entries`** and **`interpro_get_entry`** search InterPro and 14 member databases (Pfam, PROSITE, SMART, CDD, PANTHER, and others) by text, entry type, GO annotation, or integrating InterPro accession, and read one entry's full metadata. The entry database is inferred from standard accession prefixes.
- **`interpro_get_protein_domains`** maps a UniProt protein's domains, families, repeats, and functional sites to residue coordinates, optionally at one residue or with predicted features. Discontinuous fragments, models, and upstream scores are kept as returned.
- **`interpro_get_clan`** reads a Pfam, CDD, or PIRSF set, pages its members, and optionally returns its relationship graph.
- **`interpro_find_proteins_by_domain`** finds UniProt proteins carrying an entry, defaulting to reviewed human proteins (`taxonId` and `reviewedOnly` change the scope).
- **`interpro_list_reference`** decodes database slugs, entry types, accession patterns, common taxon IDs, and the current InterPro release.
- **Response budgets**: results over 100,000 bytes are cut between whole records (protein-map matches and clan relationship slices) and continue through opaque cursors bound to their query, with a notice naming the next call.
- **Request limits**: one upstream request per second process-wide, a 50-second budget per tool call, and a 4 MiB cap on upstream responses. The HTTP/1.1 client handles the API's bodyless 204 responses, which native `fetch` rejects on Node.
- **Rendering**: `content[]` carries the full output as compact JSON plus an index of every URL and image, matching `structuredContent`. Upstream text never shapes server-written Markdown or error lines.
- **Typed failures** (`entry_not_found`, `entry_withdrawn`, `invalid_cursor`, `upstream_rate_limited`, and others), each with a recovery hint.
- **Transports**: STDIO or Streamable HTTP, stateless sessions, no API key or server-specific environment variables.
