# 0.3.0 — 2026-11-15

## Added

- **`interpro_find_structures`** lists the PDB structures of a UniProt protein (`proteinAccession`) or an InterPro or member-signature entry (`entryAccession`) in PDB ID order, with experiment type, resolution (`null` where InterPro records none, as for NMR and some EM structures), and chain records. A row's `metadata.accession` and chain go to `interpro_get_structure_domains` as `pdbId` and `chain` ([#29](https://github.com/cyanheads/interpro-mcp-server/issues/29)).
- **`interpro_get_protein_domains`** maps UniProt isoforms (`P04637-2`) in the canonical row shape, and the first segment of a canonical protein lists its `isoforms`. Extra features and residue annotations stay canonical-only, so an isoform with either fails as `isoform_annotations_unavailable`; an isoform InterPro does not hold is `isoform_not_found` ([#30](https://github.com/cyanheads/interpro-mcp-server/issues/30)).
- **`limit`** on `interpro_get_protein_domains` (default 20, maximum 200), `interpro_get_structure_domains` (10, 60), `interpro_scan_sequence`, and `interpro_get_scan_result` (20, 200), and **`relationshipLimit`** on `interpro_get_clan` (20, 5,000) set the page size; larger values clamp with a notice ([#27](https://github.com/cyanheads/interpro-mcp-server/issues/27)).
- **`includeSequence`** on `interpro_get_protein_domains` returns `protein.sequence` ([#28](https://github.com/cyanheads/interpro-mcp-server/issues/28)).
- **`interpro_list_reference`** `taxa` lists taxon `1`, all organisms ([#31](https://github.com/cyanheads/interpro-mcp-server/issues/31)).

## Changed

- **Breaking: `interpro_get_protein_domains`** omits `protein.sequence` unless `includeSequence: true`; `protein.length` always gives the residue count ([#28](https://github.com/cyanheads/interpro-mcp-server/issues/28)).
- **`interpro_get_entry`** pages an `overlaps_with` array of more than 20 records at 20 per page, with `overlapsPage` and a continuation notice; `overlapLimit: 1000` reproduces the 0.2.0 reply. `overlapOffset` no longer requires `overlapLimit`, which retires `overlap_limit_required`, and `overlapLimit` above 10,000 clamps ([#28](https://github.com/cyanheads/interpro-mcp-server/issues/28)).
- **Protein maps, structure maps, scan results, and clan relationships** page by whole-record count instead of ending at a 100,000-byte budget, and `cap` reports the effective limit. 0.2.0 cursors resume at the record they name ([#27](https://github.com/cyanheads/interpro-mcp-server/issues/27)).
- **`interpro_scan_sequence`** takes `cursor` without `sequence`, resuming the precalculated walk without submitting a job. Finished results stay in memory for 10 minutes (32 MiB cap), so the pages of one walk fetch the result once ([#25](https://github.com/cyanheads/interpro-mcp-server/issues/25)).
- **InterPro requests** wait up to 32 seconds per attempt, capped at the remaining 50-second call budget, and an `upstream_timeout` (the attempt bound, HTTP 408, or HTTP 504) is not retried within the call. The pacer admits 3 requests in flight at one start per second ([#26](https://github.com/cyanheads/interpro-mcp-server/issues/26)).
- **`interpro_find_proteins_by_domain`** documents `taxonId: "1"` for all organisms. An empty result's notice offers only the selections that can still widen it and names `architectureId` when set, and an invalid `taxonId` reads "Expected a positive NCBI taxonomy identifier such as 9606, or 1 for all organisms." ([#31](https://github.com/cyanheads/interpro-mcp-server/issues/31)).
- **Development guidance and packaging checks** are synchronized with the adopted framework.

## Fixed

- **The advertised UniProt accession `pattern`** listed uppercase letters only while the server accepts any case.
- **A request that reaches the 50-second call deadline** reports `retry_deadline_exceeded` ("InterPro call exhausted its 50-second budget.", `retryable: true`, `deadlineMs` 50,000); in 0.2.0 it could surface as `upstream_timeout` ([#26](https://github.com/cyanheads/interpro-mcp-server/issues/26)).
- **`interpro_get_clan`, `interpro_get_entry`, `interpro_search_entries`, `interpro_find_proteins_by_domain`, and `interpro_list_reference`** declare `retry_deadline_exceeded` with a tool-specific recovery hint; in 0.2.0 they returned it with none ([#26](https://github.com/cyanheads/interpro-mcp-server/issues/26)).
- **`interpro_scan_sequence` and `interpro_get_scan_result`** report a status poll that reaches the deadline as "InterProScan call exhausted its 50-second budget." instead of the retry helper's internal message ([#26](https://github.com/cyanheads/interpro-mcp-server/issues/26)).
